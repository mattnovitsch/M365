# Microsoft Defender for Cloud Apps - Cloud Discovery Legacy API Export and Power BI Dashboard

> [!IMPORTANT]
> Microsoft now provides a **Microsoft Graph Cloud App Discovery API (Preview)** for working with discovered apps. The Graph API is the preferred option when that workload is available in your cloud environment because it exposes richer Cloud Discovery data, including app, user, device, and IP address detail.
>
> This project uses the **legacy Microsoft Defender for Cloud Apps API** and was created for environments where the Cloud App Discovery Graph API is not available, including the GCC and GCC High scenarios this project was designed to support.

## Overview

This project exports Microsoft Defender for Cloud Apps (MDCA) **Cloud Discovery** application data using the legacy MDCA API and makes the resulting CSV available to Power BI for reporting.

It contains two parts:

1. **PowerShell export** - Connects to the tenant-specific Defender for Cloud Apps API, finds the Defender-managed endpoints Cloud Discovery stream, retrieves discovered application information, and writes the results to CSV/JSON.
2. **Power BI dashboard** - Uses `CloudDiscoveryApps.csv` to visualize application usage, categories, traffic, transactions, risk information, and aggregate user/device counts.

The intent is to provide a reusable Cloud Discovery reporting option for Microsoft 365 Government environments where the newer Cloud App Discovery Microsoft Graph API cannot be used.

---

## Graph API version vs. this version

Microsoft documents a newer **Cloud App Discovery API in Microsoft Graph (Preview)** under:

`/beta/security/dataDiscovery/cloudAppDiscovery`

That API can retrieve uploaded Cloud Discovery streams, aggregated application details, and the users, devices, or IP addresses associated with a discovered application.

### When the Graph API is available

Use the Graph version. It provides richer data and is the version to use when you need details such as individual user identifiers.

Microsoft documentation:

- [Work with discovered apps via Graph API](https://learn.microsoft.com/en-us/defender-cloud-apps/discovered-apps-api-graph)
- [Microsoft Graph Defender for Cloud Apps API overview](https://learn.microsoft.com/en-us/graph/api/resources/security-cloudappdiscovery-overview?view=graph-rest-beta)

### GCC / GCC High

This project is the **legacy-API alternative for GCC and GCC High deployments where the Cloud App Discovery Graph workload is unavailable**.

Microsoft Graph national clouds use different service endpoints and individual Graph workloads can differ between the global and government clouds. Do not assume that because Microsoft Graph itself is available in a government cloud that every `/beta` workload is also available there.

- [Microsoft Graph national cloud deployments](https://learn.microsoft.com/en-us/graph/deployments)

> [!NOTE]
> This legacy API export does **not** provide the same level of user detail as the Graph Cloud App Discovery API. The discovered-app records include aggregate values such as `usersCount`, `machineNamesCount`, and `ipAddressesCount`, but not the individual `userIdentifier` records available through the Graph API.

## What the script exports

The PowerShell script retrieves the Cloud Discovery continuous report for **Defender-managed endpoints** and exports discovered applications.

The CSV contains the following fields used for reporting:

- Stream ID and stream name
- Application name
- Category
- Domains
- First and last observed dates
- Location
- Organization
- MDCA risk score
- Cloud Discovery time-frame data
- Total traffic
- Uploaded traffic
- Transactions/events
- User count
- Device count
- IP address count
- Blocked event count
- Application description

Category values are cleaned during export so values such as:

`SAASDB_CATEGORY_CLOUD_COMPUTING_PLATFORM`

are exported as:

`CLOUD_COMPUTING_PLATFORM`

## Find the MDCA API information

The legacy API uses the tenant-specific Defender for Cloud Apps endpoint.

In the Microsoft Defender portal, go to:

**Settings > Cloud Apps > System > About**

The API host follows this general pattern:

`https://<tenant>.<region>.portal.cloudappsecurity.com`

For example, if the API host is:

`https://contoso123.us2.portal.cloudappsecurity.com`

then:

- **MDCATenant:** `contoso123`
- **MDCARegion:** `us2`

Microsoft documents the legacy MDCA REST API URL and `Authorization: Token` authentication model here:

- [Defender for Cloud Apps REST API](https://learn.microsoft.com/en-us/defender-cloud-apps/api-introduction)

---

## API token

A legacy Defender for Cloud Apps API token is required.

The script supports storing the token as a parameter/default value or supplying it when the script is launched.

> [!WARNING]
> Treat the API token as a secret. If a token is stored directly in the `.ps1` file, **do not commit that populated token to GitHub**. Publish the script with an empty token value and have each user insert their own tenant token locally.

## Run the export

Example:

```powershell
.\Get-MDCACloudDiscoveryLegacy.ps1 `
    -MDCATenant "contoso123" `
    -MDCARegion "us2" `
    -TimeFrameDays 90
```

The script queries the Cloud Discovery continuous-report API, identifies the Defender-managed endpoints stream, retrieves the discovered applications, and exports the results.

The output includes:

- `CloudDiscoveryApps.csv` - optimized for Power BI / Excel
- `CloudDiscoveryApps.json` - fuller representation of the API response
- `ContinuousReports.csv`
- `ContinuousReports.json`
- Raw API response JSON used for troubleshooting

## Supported reporting periods

The continuous report advertises the reporting periods available for that tenant. Common periods include:

- 7 days
- 30 days
- 90 days

Use the `-TimeFrameDays` parameter to select the desired reporting period.

Example:

```powershell
-TimeFrameDays 90
```

Point the Power BI `CsvPath` parameter at the generated file:

`CloudDiscoveryApps.csv`

## User reporting limitation

The legacy API and the Microsoft Graph API are not equivalent.

The Graph Cloud App Discovery API documents endpoints for retrieving the individual users, devices, and IP addresses associated with an application. This legacy export receives aggregate app-level fields such as:

- `usersCount`
- `machineNamesCount`
- `ipAddressesCount`

As a result, the Power BI report can show **how many users** accessed an application, but it cannot reproduce a Graph-backed report that lists the individual user identifiers.

If individual user-level Cloud Discovery reporting is required, use the Graph Cloud App Discovery API when that workload is available in the target cloud.

## How the legacy API is used

The project uses the tenant-specific Defender for Cloud Apps API with legacy token authentication:

`Authorization: Token <API token>`

It first retrieves the Cloud Discovery continuous reports and then works with the discovered application information associated with the Defender-managed endpoints report.

## Troubleshooting

### No continuous reports are returned

Confirm that Cloud Discovery data exists in the tenant and that a continuous report is available. Defender for Endpoint integration is one documented source of continuous Cloud Discovery data.

### API authentication fails

Verify:

- The MDCA tenant name
- The MDCA region
- The legacy MDCA API token
- The tenant-specific API URL shown under **Settings > Cloud Apps > System > About**

### Power BI cannot find the CSV

Update the `CsvPath` parameter in Power BI to the current location of `CloudDiscoveryApps.csv`, then refresh the dataset.
